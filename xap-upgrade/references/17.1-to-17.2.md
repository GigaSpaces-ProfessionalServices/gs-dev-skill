## Deprecation in this window

**REST API V2 (and the V2-based ops-ui) is deprecated as of 17.2**, alongside the introduction of
REST API V3. Per that release's own notes: "The V2 manager remains active alongside V3, but is
deprecated and will be removed in a future version. The ops-ui, which is based on the V2 API, is
also deprecated." A team's automation, scripts, or tooling still calling the V2 manager API or
relying on ops-ui has a real migration to plan for — not urgent (V2 is still active in 17.2), but
on notice for a future removal not yet dated.

**V3 isn't started by default alongside the manager — it needs its own flag.** Per the same
release's notes, starting the manager with `./gs.sh host run-agent --manager` alone does not bring
up REST API V3 or SpaceDeck; both need to be explicitly requested with `--restv3 --webui`, e.g.
`./gs.sh host run-agent --manager --restv3 --webui`. A grid started without those flags is still
running V2/ops-ui only, regardless of which XAP version it's on — worth checking startup
scripts/automation for this after upgrading, since the deprecation above only matters once V3 is
actually running.

**`metrics.xml` is deprecated in favor of `metrics.properties`.** 17.2.0-ga ships both files
transitionally (metrics moved to a Micrometer.io-based framework, with the new
`metrics.properties` format alongside the legacy XML one); by 17.2.2, `metrics.xml` is dropped from
the distribution entirely — only `metrics.properties` remains. Per that release's own notes:
"Metric configuration has shifted from XML to a centralized properties file located at
`gs-home\config\metrics\metrics.properties`." Out of the box, `metrics.properties` replaces
`metrics.xml`'s functionality with no action needed — the migration only matters for a project that
customized/enhanced its own `metrics.xml` (e.g. a configured InfluxDB reporter), since that
customization needs to be reviewed and re-expressed in the new format
(`metrics.registries=...`) rather than assumed to carry over automatically.
