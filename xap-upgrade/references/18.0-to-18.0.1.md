# XAP Upgrade: 18.0 → 18.0.1

> Verified against releases **18.0.0** and **18.0.1** (GA) specifically, by comparing jar
> versions and the distribution layout. See `references/dependency-compatibility-checklist.md` for what these numbers mean and
> why they matter.

18.0.1 is a patch step: no JDK change and no major dependency bump. The breaking changes for the
18 line (Java 25, V2 REST Manager retired) are in 18.0. If you are coming from 17.x, read
`17.3-to-18.0.md` first.

| Component | 18.0 | 18.0.1 |
|---|---|---|
| Java | 25 | 25 (unchanged) |
| Spring Framework | 7.0.9 | 7.0.10 (patch only) |
| Spring Security | 7.1.1 | 7.1.2 (patch only) |
| Spring Boot Loader | 4.1.1 | 4.1.2 (patch only) |
| Jetty | 12.0.38 | 12.0.38 (unchanged) |
| Hibernate | *(project-supplied; not bundled by XAP)* | 7.1.0.Final confirmed working with a Hibernate-backed Mirror on Spring 7.0.10; see `xap-persist`'s `mirror-service.md` |
| Default lookup group | `xap-18.0.0` | `xap-18.0.1` |

## Changes to check

- **Align your own Spring pins.** A project that pins Spring Framework explicitly should move to
  `7.0.10`, and a Spring Boot client application to Boot `4.1.2`, which is what 18.0.1 bundles.
  An older explicit pin next to XAP's transitive Spring produces a split classpath that fails at
  startup (checklist #2).
- **The V2 web app is gone from the distribution.** `lib/optional/rest/` (`xap-rest.war`,
  `xap-rest-spring.jar`) is no longer shipped. It wasn't served in 18.0 either, so nothing
  running stops working. Only a build or script that copies those files from `$GS_HOME` breaks.
- **Default lookup group changes again** to `xap-18.0.1`. Set `GS_LOOKUP_GROUPS` or locators
  explicitly so clients and grid don't depend on the version-derived default.
- **Rebuild against the 18.0.1 jars.** Update `gigaspaces.version` in every `pom.xml`. Client and
  server versions should match (checklist #4).
